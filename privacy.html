Privacy policy

DriveCast is a local Python control panel operated through the thenaimatullahmajeed GitHub account. Each configured client has one video source, Google Drive or supported public Instagram professional media, and an individually authorized YouTube destination and an optional authorized Facebook Page. This policy covers the tool and this public information website.

Data accessed and why

  • Google Drive: configured folder names, IDs and capabilities; queued video names, IDs, creation dates, parents, descriptions and contents; and optional text/JSON metadata. This identifies candidates, downloads videos, reads metadata and organizes files.
  • YouTube: authorized channel ID/title and available subscriber, view and video counters; uploaded video contents, title, description, tags, privacy/category settings and resulting video IDs. These support exact destination checks, uploads and a channel overview. Per-video view, like and comment counts support the records view. The tool does not request revenue or watch-time analytics.
  • Instagram/Meta: the operator-authorized professional account and linked Facebook Page IDs; supported public professional target profile IDs, usernames and counters; available media IDs, captions, timestamps and download URLs. These support source validation, caption-based metadata, video transfer and duplicate protection. The official Business Discovery route does not collect client Instagram passwords or bypass private account access.
  • Facebook Pages: selected Page names/IDs and access tokens, uploaded video contents, video IDs and supported insights are used to verify the Page, publish the same authorized source video and display available counters. Each destination maintains a separate ledger.
  • Authorization: OAuth client identifiers/secrets, separate Google refresh tokens, authorized GitHub tokens and Meta user/Page access tokens and the operator's Meta app ID/secret. Temporary access tokens permit platform requests. Google, GitHub and Meta handle their own sign-in.
  • Configuration and history: client labels, pinned source/channel/repository IDs, cached stats and check dates, filenames, attempts, status, video IDs, errors and workflow links. These support recovery, a daily attempt limit and review of uncertain uploads.

Permissions and source choice

YouTube authorization requests youtube.upload and youtube.readonly. A separately approved Drive connection requests broad drive access; the worker processes the configured folder and its Processing, Done and Failed subfolders. Drive and YouTube can use different Google accounts.

The optional Meta connection uses the official Instagram API with Facebook Login and relevant professional-account/Page read permissions. App setup, approved access, account eligibility and available media URLs govern what is accessible. A username alone does not grant unrestricted access or permission to republish content.

Facebook Page posting uses separately authorized Page management/publishing permissions and optional insights permission. Meta login uses an HTTPS localhost callback; its generated localhost certificate/private key stay in ignored local work data. No trust certificate is installed automatically.

Processing and storage

  • Saved connection credentials are encrypted locally using AES-GCM with a Scrypt-derived key from the operator's Recovery Password. The password is not uploaded or saved as plaintext. Optional remembered unlock uses Windows DPAPI, bound to the original Windows account/device. Credentials are available in process memory while unlocked.
  • Nonsecret settings and cached stats are stored locally; a local SQLite database holds history, with dated local snapshots. A dedicated private GitHub recovery repository can hold configuration, combined records and a copy of the encrypted vault. Portable credential recovery is ready only after the vault is populated and checkpointed.
  • Each private pipeline repository holds code, nonsecret variables and sealed GitHub Actions Secrets. A separate state branch holds an upload ledger containing source identifiers, filenames/captions, attempts, errors, statuses and accepted YouTube IDs. GitHub CLI also manages its native local GitHub sign-in.
  • GitHub Actions runners download videos to temporary files and transfer them to YouTube. Normal processing cleans up temporary files; interrupted jobs may retain data until the runner is disposed of.
  • Drive source videos remain in Drive and move to Processing, Done or Failed. Success records the YouTube ID in the Drive description. Drive daily-counter properties and the GitHub ledger support conservative retry handling. Instagram source media is not edited or deleted by this tool.
  • YouTube stores accepted videos under the effective privacy setting. Normal workflows request Public; an optional private YouTube test forces Private and does not post to Facebook. Provider restrictions can also prevent public publication.
  • Sync tests connections, reads source/channel counters, imports workflow records and checkpoints recovery data. It does not start uploads. The current implementation derives basic metadata from supplied filenames, sidecars and captions without sending them to AI providers. The single-file Export encrypts workspace, connections, records and stats using the existing unlock password; Import previews decrypted counts before confirmed restore. Source checks use an operator-selected interval and read-only counter jobs run every six hours.

Sharing and access

Google receives requests to access Drive and upload/read YouTube data; Meta supplies supported Instagram data; GitHub stores code, secrets, history and encrypted recovery, and executes workflows. Authorized repository owners/collaborators can access repository metadata and logs. Repository owners can modify workflows that use stored Secrets. A local-only control panel does not remove that repository authority; use trusted accounts and restrict access.

DriveCast does not sell Google user data or use it for advertising, general-purpose AI model training or unrelated profiling. DriveCast's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

This public website

These static information pages have no account sign-in, credential forms, analytics scripts or advertising cookies. They do not host client videos, client history or secrets. GitHub Pages may process request information under the GitHub Privacy Statement.

Retention, revocation and deletion

Pause affected pipelines first. Revoke Google permission at Google Account connections, review Meta access in Facebook Business integrations, and revoke GitHub authorization in GitHub applications settings. Expired or revoked access may require reconnection; no permanent-token guarantee is made. Revocation does not delete existing videos, source media, logs or backups.

To remove stored data, delete the relevant repository Secrets/variables, workflow logs, state/recovery repositories as appropriate, and local work data including the encrypted vault, remembered unlock, SQLite records and backups. Close the process to clear active memory. Removing one file from the latest Git commit does not remove earlier Git history or provider retention copies; use the provider's deletion/history procedures where needed. Review uncertain uploads before deleting queue/history markers, because losing those markers can weaken duplicate protection.

Manage existing videos in YouTube Studio and source files in Drive/Instagram. For assistance, contact thejunaidaziz@gmail.com with the client/channel involved; never send passwords, tokens or secret JSON. Changes to this policy will be published with an updated effective date.
