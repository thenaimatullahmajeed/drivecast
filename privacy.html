Privacy policy

DriveCast is a locally configured Python uploader operated through the thenaimatullahmajeed GitHub account. It connects selected Google Drive folders to individually authorized YouTube channels. This policy covers the tool and this public information website.

Data accessed and why

  • Google Drive: the configured folder’s name, ID and capabilities; names, IDs, creation dates, parents, descriptions and contents of queued video files and optional text/JSON metadata. This data identifies candidates, downloads videos, reads upload metadata and organizes files.
  • YouTube: the authorized channel’s ID and title, channel handle resolution, uploaded video contents, titles, descriptions, tags, privacy and category settings, and resulting video IDs. These support channel verification and uploads.
  • Authorization: OAuth client identifiers, client secrets and separate refresh tokens for Drive and YouTube. The tool uses these to obtain temporary access tokens. Google handles Google account sign-in; DriveCast does not ask for Google passwords.
  • Configuration and logs: client labels, folder/channel IDs, repository links, status, filenames, upload progress, resulting video IDs and errors for setup and troubleshooting.

Google permissions

DriveCast requests drive for Drive access, youtube.upload for uploads, and youtube.readonly for channel verification. The Drive permission is broad; the uploader’s implementation processes the configured folder and its Processing, Done and Failed subfolders. The operator should grant access only from appropriate accounts. Drive and YouTube use separate approval flows so a YouTube-only Brand Account is not asked to grant Drive access.

How data is processed and stored

  • During local setup, Google client credentials and refresh tokens are held in the setup process’s memory. The tool does not write them into its local client state file.
  • On deployment, credentials are stored as encrypted GitHub Actions repository secrets. Authorized repository administrators and workflows control their use. GitHub CLI separately manages its own GitHub sign-in.
  • Local setup state stores nonsecret configuration and status on the operator’s computer. Private repository variables hold nonsecret upload settings.
  • GitHub Actions runners download videos to temporary files and upload them to YouTube. Temporary files are cleaned up when processing exits normally; hosted runners are disposable. Data may be present on a runner during an interrupted job.
  • The source Drive files remain in Drive. The uploader moves them into Processing, Done or Failed, records a successful YouTube video ID in the file description, and stores a date and daily-attempt counter in the source folder’s properties.
  • Uploaded videos remain on YouTube under the selected privacy settings. A metadata sidecar can override the default privacy. Operators must review metadata and settings before uploading.
  • GitHub Actions logs and repository configuration remain until deleted or expired under the repository’s retention settings. Tokens are not intentionally printed; the operator must keep workflow access and logs secure.

Sharing and limited use

Data is sent to Google to access Drive and upload videos to YouTube, and to GitHub to store automation configuration/secrets and run workflows. The operator and authorized repository collaborators may access configuration and logs. Public uploads become visible on YouTube according to the selected visibility. DriveCast does not sell Google user data or use it for advertising, general-purpose AI model training or unrelated profiling.

DriveCast’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

This public website

This website has no Google sign-in, credential collection, analytics scripts or advertising cookies. GitHub Pages hosts the public pages and may process request information such as IP addresses and technical logs under the GitHub Privacy Statement. This website does not host client videos or automation secrets.

Retention, revocation and deletion

Pause the client’s scheduled workflow before changing access. You can revoke Google access at Google Account connections. Revocation prevents future authorized API access; it does not delete existing files, videos, logs or repository secrets.

To remove stored configuration and credentials, delete the relevant repository secrets/variables, workflow logs and local client state, or delete the private automation repository if it is no longer needed. Close the setup process to discard credentials in its memory. Delete uploaded videos in YouTube Studio and source files or upload markers in Drive if desired. Only reset queue/history markers after reviewing uncertain uploads.

For assistance with data access or deletion, contact thejunaidaziz@gmail.com. Identify the client/channel involved; never email passwords, client-secret JSON or refresh tokens.
